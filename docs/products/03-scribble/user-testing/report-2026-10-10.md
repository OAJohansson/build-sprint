# User test: Scribble, 2026-10-10

**Persona:** Robin, 32, works in tech, wants to write a little and often and is put off by blank pages and grading · **Method:** simulated (agent), phone viewport 390×844 (plus one check at 1440 desktop width) · **Build:** `3f4244b` on the local dev server (in-memory store, sample reader)

## Verdict
"It's the first writing thing that doesn't ask me anything first. I tap and I'm typing, and the reader quoted my own sentence back to me without rewriting it. I'd keep it for a week. What would stop me is that the red text gets hard to read in bed. And when I set a piece down on the bus and put the phone away, it never gets a reader."

## Value
- **Earns its place:** the prompt-first blank page (I'd use it daily), the quoted, non-grading reply with one thing to try, the "last time: end on an image, not a feeling" line (a quiet nudge, not homework), and "+2" past the goal with no guilt.
- **Doesn't (yet):** the goal card (set once and forget it), the key-sound toggle, and export (good for trust, but I'd never use it weekly).
- **Missing that would bring them back tomorrow:** the reader always available on yesterday's piece (F1), and some sign that the lessons add up.

## Progress
**Can see:** this week's count (marks, "this week: 6 of 4"), a dated list with word counts, which pieces have a reply, and the last lesson only.
**Can't see:** anything across weeks, what I keep doing well, the lessons I've collected, or whether my pieces are getting longer.
**Most valuable view to add:** a "what you're practising" section at the top of *your pieces*. It lists each lesson the reader gave ("one concrete detail beats three", "put the funny word last", "end on an image") with the number of pieces since, and taps through to the piece that taught it. It answers "what am I getting better at?" (job 3) using data that's already saved.

## Top recommendations
1. Add "Ask for a reader" on any finished piece without a reply (F1).
2. Raise the red ink contrast to at least 4.5:1 in Night first, then Manuscript (F2, F3).
3. Send the save when the page is hidden, so closing straight after typing loses nothing (F6).
4. Keep the original prompt once text exists, and refocus after a swap (F5).
5. Add the "what you're practising" lesson list in *your pieces*, and auto-scroll the reply (job 3, F4).

## Method notes
- **Simulated:** typing by keyboard, not a phone keyboard. The reader is the fixed local SAMPLE (about 1.4 s), so real Claude speed and quality weren't judged. Seeded pieces all have today's date, so marks across real weekdays and a real Monday piece weren't seen.
- **Start state:** the in-memory store held a 1,981-word draft left over from break-ui testing; the tester blanked it through the API to get a first-run state.
- **Dev overlay:** the Next.js "N" button covers the start of "↻ not this one" in the screenshots. It's dev-only and wasn't scored.

**Guardrails, measured:**

| Guardrail | Result |
| --- | --- |
| Time to first word | ~20 s for a person on first run (unlock, read the prompt, tap, type), 6–8 s for a returning user (scripted: 4.9 s) |
| Taps to first word | 3 on first run (code field, open, page), 1 after that |
| Feedback checklist (sample reply) | Quotes their words, one strength, one suggestion, no rewrite, kind: 5 of 5 on its shape |
| Data safety, same device reload | Exact |
| Data safety, second browser after the save | Exact |
| Data safety, second browser when closed 0.3 s after typing | Last 4 words missing (F6) |
| Export | Has all 6 finished pieces with their replies, plus the open draft |
